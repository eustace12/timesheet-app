# Urchin People — оценка и релиз от 2 ноября 2026

Проверку независимо выполняли критик продукта/UIUX, тестер и разработчик рабочего режима. Исправления реализованы, проверены и опубликованы в отдельном публичном демо. Дополнительно собран и запущен рабочий контейнер с корпоративной моделью доступа.

Оценка: прежде это был функциональный демонстрационный прототип. Сейчас подготовлен релиз узкого продукта для месячных таймшитов, отпусков и работы бухгалтера. Запуск на реальных данных компании ещё требует интеграции с её действующим SSO, выбранным окружением и проверенными резервными копиями. Публичный адрес остаётся демонстрационным и не является таким запуском.

## Проверки

- 148 Python tests passed, без пропусков, включая настоящий временный PostgreSQL 16, конкурентные запросы, миграции и права RPC.
- 30 Node/DOM tests passed, включая production-интерфейс без profile/demo selector.
- В чистом окружении проверены текущие закреплённые зависимости. Остались предупреждения об устаревающих API сторонних ReportLab/openpyxl на Python 3.12; ошибок выполнения нет.
- Python dependency audit и npm audit: известных уязвимостей не найдено. Это не утверждение об отсутствии любых неизвестных уязвимостей или отдельный аудит пакетов ОС базового образа.
- Helm lint/render прошли с явными тестовыми параметрами; отсутствие обязательной конфигурации блокирует рендеринг.
- Собран Linux/amd64 image `urchin-people:company-20261102`; uid10001, read-only root, scratch только в /tmp.
- Запущенный image: readiness 200 с настоящими БД и приватным bucket изолированного демо; без identity 401, один поддельный email 401, employee → admin 403, legacy download 404, собственный monthly 200.
- Внутри контейнера проверена генерация PDF и Excel в рабочем профиле. Сборка без обязательной защищённой конфигурации не запускается.
- Проверены RPC через настоящую Data API: отсутствующий сотрудник отклоняется атомарно, отсутствующий документ остаётся отсутствующим. Эти проверки не создают записей.
- В браузере проверены опубликованные месяцы, Other, совпадение часов PDF, мобильные командные балансы и рабочий интерфейс контейнера без демо-переключателей.
- Локальный adapter для скриншота контейнера передавал синтетическую SSO identity. Проверка настоящего IdP компании и его ingress ещё не выполнена.
- CI release gates добавлены в репозиторий; удалённый CI pipeline в этой работе не запускался.

## Что требуется для боевого включения

1. Конкретные company cluster/context, namespace, домен/TLS, registry и выбранный проект постоянного хранения. Chart и инструкции готовы; в компанию ничего не применялось.
2. Действующий oauth2-proxy/ingress: проверка провайдера и tenant, перезапись identity headers, доставка существующих runtime Secrets, NetworkPolicy с точными селекторами proxy.
3. Реальные профили, соответствие SSO email → username, роли и согласованные годовые лимиты. Демо-профили не переносятся.
4. Резервное копирование и проверенное восстановление БД вместе с файлами. Нынешняя проверка миграции не заменяет restore drill.
5. Приёмка реального HTTPS SSO маршрута сотрудником и бухгалтером, наблюдение после запуска и сохранённый предыдущий image/tag для rollback.

Правила отпуска при ненастроенном лимите нужно определить при заведении компании: сейчас это явно показанный режим без предполагаемого установленного законом лимита. Для использования ограничений сначала задаются реальные allowances.

## Границы V1

Внешние уведомления, отмена/отзыв отпуска, автоматическое начисление/перенос лимита и payroll не включены. Черновики сохраняются в браузере, синхронизации черновиков между устройствами нет.
